The absence of shared live image references means the user’s “copied multiple times at product images” symptom is not explained by duplicate API product records or identical stored URLs in the current 20-product response. The likely remaining causes are repeated visual assets inside mockup/gallery compositions, fallback image behavior on failed URLs, or missing seed products causing a smaller/incorrect product set to be perceived as duplicates. `ProductDetail.tsx` deduplicates exact gallery URLs with `new Set(...)`; `ProductCard.tsx` renders one main image per product and uses category-specific fallback paths.

The current `mockups.tsx` shared specification is only partially canonical. It has shared print zones and source-kit paths, but its comments explicitly record colored hoodie and long-sleeve front-only photo coverage, with colored backs falling through to tint paths. It defines separate front/back constants and many per-color front assets, making front/back color consistency a known defect. It also includes runtime safeguards against duplicate full-frame base passes, confirming that ghost silhouettes/wedges have previously occurred.

The current `AdminOrders.tsx` UI already contains sections for design previews, order notes/payment evidence, payment-proof links, parsed `customNote` studio metadata, original asset zip download, and custom image thumbnails. The API order route also attempts to preserve `customNote`, `customImages`, `originalAssetUrls`, `originalAssets`, and uploaded studio preview images.
