1. PROJECT OVERVIEW
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Trynext Lifestyle is a Bangladeshi print-on-demand e-commerce platform. Customers
can browse products (T-shirts, hoodies, mugs, caps, water bottles), use a
browser-based Design Studio to upload/position artwork and preview results in 2D
or 3D, then order with COD or bKash/Nagad (25% advance deposit required for COD).

Products: Custom T-shirts, Hoodies, Mugs, Caps, Water Bottles, Couple Sets,
          Hampers (gift bundles), Corporate Bulk Orders.
Target market: Bangladesh (all 64 districts). Currency: BDT (৳).
Brand: Orange (#FF6B2C) on cream/dark background. Font: Geist. Logo: TN mark.

MONOREPO
  - pnpm workspaces (pnpm-workspace.yaml)
  - TypeScript throughout; `pnpm run typecheck` checks all packages
  - Node 20+

STOREFRONT + ADMIN (artifacts/trynex-storefront)
  - Vite 7 + React 19 + TypeScript
  - Tailwind CSS v4 + shadcn/ui components
  - Wouter (lightweight React Router)
  - TanStack Query v5 (server state)
  - Framer Motion (animations)
  - react-helmet-async (SEO)
  - Vite PWA plugin (service worker, offline support)
  - Port: $PORT (default 8080 in dev via workflow)
  - Dev proxy: Vite proxies /api/* → localhost:8082 (the API server)

API SERVER (artifacts/api-server)
  - Express 5 + TypeScript
  - esbuild bundle (NOT a dev-watch process — must rebuild manually)
  - Pino logging (JSON structured logs)
  - Zod input validation
  - express-rate-limit (multiple limiters)
  - Helmet.js (security headers)
  - Port: $PORT = 8082 (set in workflow command)
  - CRITICAL: After editing any src/ file, run: cd artifacts/api-server && node build.mjs
    Then restart the "artifacts/api-server: API Server" workflow.

DATABASE
  - PostgreSQL via Neon (serverless)
  - Drizzle ORM + drizzle-kit migrations
  - Schema: lib/db/src/schema/index.ts (single source of truth)
  - Connection failover chain (priority order):
      1. DATABASE_URL_MAIN  (Neon primary — ep-proud-hill)
      2. DATABASE_FAILOVER  (Neon failover — ep-crimson-dawn) ← currently active
      3. DATABASE_URL_TRYNEXT_DB (Neon secondary)
      4. DATABASE_URL       (Replit built-in — last resort)
  - Status: Primary (DATABASE_URL_MAIN) unreachable; fallback #2 is working fine.
  - Backup sync: scheduled every 30 min to 3 replica shards — all 3 hitting Neon
    data-transfer quota limits (not a code bug; requires Neon plan upgrade or
    disabling those backup targets in admin).

CACHE
  - Upstash Redis (REST API — works in edge/serverless environments)
  - Env vars: UPSTASH_REDIS_REST_URL + UPSTASH_REDIS_REST_TOKEN
  - Used for: product list cache (60s TTL), settings cache, rate limiting counters

OBJECT STORAGE
  - Primary: Cloudflare R2 (S3-compatible)
  - Fallbacks: S3, then local filesystem (./uploads)
  - Admin selects in: Admin → Settings → Storage
  - Env: R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY, R2_BUCKET

MOBILE APP (artifacts/trynext-mobile)
  - Expo SDK 54 + React Native + TypeScript
  - TanStack Query v5
  - Expo Router (file-based routing)
  - API base: EXPO_PUBLIC_DOMAIN env var → https://{domain}
  - Dev: workflow injects EXPO_PUBLIC_DOMAIN=$REPLIT_DEV_DOMAIN
  - Production: should use trynext.pages.dev (see fix applied below)
  - Port: $PORT (8084 in dev)

HOSTING
  - Storefront: Cloudflare Pages (trynext.pages.dev + trynext.pages.dev)
  - CF Pages Functions: functions/api/[[path]].ts — proxies /api/* to API_URL
  - CF Pages env var REQUIRED: API_URL = https://<your-api-host> (no trailing slash)
  - API Server: currently hosted on Replit dev domain; deploy separately to
    Railway/Render/Fly.io/CF Workers for production

NOTIFICATIONS

  - Email: nodemailer + SMTP (SMTP_HOST, SMTP_USER, SMTP_PASS, SMTP_FROM)

AI

8. DESIGN STUDIO (artifacts/trynex-storefront/src/pages/design-studio/)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Key files:
  mockups.tsx          Garment mockup rendering (SVG cutouts, garment colors)
  composer.ts          Canvas compositor (layers → final PNG for order)
  ProductViewer3D.tsx  Three.js 3D preview (PhotoMockupMesh — billboard approach)
  DesignStudio.tsx     Main page (state machine, 2D canvas editor, product switch)

Garment rendering pipeline:
  1. White/light garments: multiply-blend mode (cutout shadow + full photo with
     mix-blend-mode:multiply). Uses transparent cutout PNG + color tint.
  2. Dark/black garments: full dark garment photo directly (no multiply needed).
  3. Colored garments (navy, red): AI-generated real photos from colorPhotos map.
  4. 3D preview: PhotoMockupMesh (billboard plane textured with garment photo).
     GLB models are NOT used (files were absent; billboard approach replaces them).

Print zone system:
  - Each product has a defined print zone (x, y, width, height as % of canvas).
  - Designs are fitted to the print zone with contain-fit on product switch.
  - "Outside print area" warnings use bleed-relative tolerance + rotation-aware bounds.
  - Canvas is 2D (flat, precise placement); curvature only in 3D preview + composer.

Curved products (mug, waterbottle, cap):
  - Default view mode is "3d" so cylindrical curvature is visible by default.
  - Flat apparel defaults to "2d" for precise placement.

Design file handling:
  - Customer uploads go to /api/storage (temp staging).
  - On order placement, files are copied to permanent order folder.
  - studioAssetsMissing flag on order if any file copy fails.

Drag & rotate on canvas:
  - No pointer restriction; filterTaps:true; threshold:1.
  - Rotate handle: SVG circle above selection box, rotateHandle memo.
  - Image layers use transparent hit-rect overlay for reliable drag.

14. CODE CONVENTIONS & CRITICAL RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

API SERVER REBUILD RULE (CRITICAL):
  - The API is an esbuild bundle — it does NOT hot-reload.
  - After ANY change to artifacts/api-server/src/**:
    cd artifacts/api-server && node build.mjs
    Then restart the workflow: artifacts/api-server: API Server

GITHUB PUSH RULE:
  - git CLI is blocked in Replit (askpass intercepts credentials).
  - Use GitHub REST API (blobs/trees/commits endpoint) to push.
  - Or use x-access-token:$TOKEN in the remote URL:
    git remote set-url origin https://x-access-token:${GITHUB_ACCESS_TOKEN}@github.com/georgelsmith333-hub/trynext-lifestyle.git
    git fetch origin && git merge origin/main --allow-unrelated-histories
    git push origin main

SETTINGS RULE:
  - Never hardcode phone numbers, payment numbers, shipping costs, or config values.
  - Always read from useSiteSettings() hook (storefront) or api.getSettings() (mobile).
  - Fallback pattern: (settings.whatsappNumber || settings.phone || "8801903426915").replace(/[^0-9]/g, "")

CORS RULE:
  - ALLOWED_ORIGINS must include ALL origins that will call the API.
  - In development: include your Replit dev domain.
  - In production: https://trynext.pages.dev,https://trynext.pages.dev

DB RULE:
  - Schema changes go in lib/db/src/schema/index.ts.
  - Run drizzle-kit migrations (migrations in lib/db/drizzle/).
  - Never alter the DB directly; always use migrations.

HEALTH ENDPOINT RULE:
  - systemHealth.ts is the ONLY source for GET /api/admin/system/health.
  - Do NOT add a competing handler in health.ts (it would silently win due to mount order).
  - The response shape: { services: { ... }, vars: [...] }

SCROLL LOCK RULE:
  - Route all body scroll locking through the shared ref-counted helper.
  - Never set document.body.style.overflow directly in components.

BLEND MODE RULE:
  - multiply blend threshold must match isLightTint (lum > 0.92).
  - Using 0.58 causes "same shade" bug on colored garments.

PHOTO MOCKUP RULE:
  - Do NOT use adjustGarmentColor() for photo planes in 3D.
  - near-white (lum > 0.88) must return "#ffffff" exactly.

ADVANCE DEPOSIT: Always 25% (changed from 15% across all files).

AnimatePresence: mode="wait" causes white screen on navigation — use mode="sync"
or omit mode entirely.

PRODUCT_TAB_ICONS: Must be {} (empty object) to show photo tabs in Design Studio.

ICON NAMING: Hoodie/longsleeve mockup assets use *-cutout-real.png (NOT -cutout.png).

15. HOW TO INVESTIGATE & FIX ISSUES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

"No products showing in storefront":
  1. Check Vite proxy port: artifacts/trynex-storefront/vite.config.ts
     Line: const apiPort = process.env.API_PORT ?? "8082"  ← must be 8082
  2. Check API is running: curl http://localhost:8082/api/products?limit=1
  3. Check proxy works: curl http://localhost:8080/api/products?limit=1
  4. Check browser console for CORS errors or 502/503
  5. Check ALLOWED_ORIGINS in API env vars includes the storefront origin

"API server won't start":
  1. Check all required env vars are set (ADMIN_JWT_SECRET, JWT_SECRET, etc.)
  2. Run: cd artifacts/api-server && node build.mjs (rebuild first)
  3. Check workflow logs for the specific error

"DB connection failing":
  1. Check lib/db/src/index.ts failover chain — which URL is being tried?
  2. Verify Neon project is not paused (Neon dashboard → check project status)
  3. Try connecting with psql to each DATABASE_URL_* to find which works
  4. The server will still start even if all DBs fail; queries will throw

"Mobile app can't reach API":
  1. In dev: EXPO_PUBLIC_DOMAIN must be set to the Replit dev domain
     (workflow command sets this: EXPO_PUBLIC_DOMAIN=$REPLIT_DEV_DOMAIN)
  2. The Vite proxy must be running (storefront workflow) — mobile goes through it
  3. Verify: api.ts getBaseUrl() returns correct URL for the environment

"Backup sync failing":
  1. These are Neon quota errors — not code bugs.
  2. Check Admin → Backup → Sync Status (AdminBackup.tsx)
  3. Circuit breaker: after 3 consecutive all-failed runs, sync pauses 2 hours.
  4. Fix: upgrade Neon plan or disable failing targets

"WhatsApp links broken":
  1. Check Admin → Settings → phone + whatsappNumber fields are filled.
  2. All WA links should use useSiteSettings() hook with fallback.
  3. Never hardcode phone numbers in JSX.

"Cloudflare Rocket Loader breaking the site":
  1. vite.config.ts adds data-cfasync="false" to all script tags automatically.
  2. If Rocket Loader is enabled in CF dashboard, disable it there as well.

"Admin login not working":
  1. Check ADMIN_JWT_SECRET and ADMIN_PASSWORD env vars are set.
  2. Admin sessions are in admin_sessions table (token-based, not JWT cookie).
  3. Tokens stored in sessionStorage as trynext_admin_token.

"Design Studio 3D preview blank":
  1. GLB models are NOT used — billboard approach (PhotoMockupMesh) instead.
  2. Check that garment photo files exist in public/mockups/.
  3. ProductViewer3D.tsx uses useGLTF.preload calls — all should be commented out.
